# Инструментите на бота

Чатът без инструменти е модел, който говори за SEO. С тях е асистент, който
гледа твоя сайт, твоя Search Console и твоя Analytics и отговаря с числа
оттам.

Всички са дефинирани на едно място — `src/lib/tools.ts` — и се извикват по
два пътя: от бота в разговор и директно от бутоните в таблото през
`POST /api/tools`. Един и същ код зад двата пътя значи, че поправка на
инструмент важи и за двата.

## Правилата

- **Инструмент никога не си измисля данни.** Няма ли достъп, казва го, и
  ботът предава това на потребителя вместо да гадае.
- **Кредитите се теглят преди изпълнението.** Обратното значи, че скъпа
  проверка, прекъсната по средата, е безплатна — и че лимитът е пожелание.
- **Домейнът идва от акаунта, не от подканата.** Иначе ботът може да бъде
  придуман да обхожда чужд сайт от името на потребителя. Само
  `compare_competitor` приема чужд адрес и той пак минава през пълната
  проверка срещу вътрешни мрежи.

## Списък

| Инструмент | Кредити | Какво прави |
|---|---:|---|
| `analyze_page` | 2 | Пълен технически и GEO одит на една страница: заглавия, мета данни, schema.org, достъп за AI ботове, llms.txt, скорост, сигурност, достъпност. |
| `crawl_site` | 8 | Обхожда много страници и връща технически резултат, покритие със schema, счупени адреси, дублирани заглавия. |
| `check_ai_visibility` | 10 | Задава реални въпроси на двигателите **с живо търсене** (ChatGPT, Claude, Grok, Gemini…) и проверява дали брандът е споменат. Основната мярка за GEO. |
| `suggest_visibility_queries` | 1 | Съставя въпросите за проверка — естествени изречения, не ключови думи. |
| `compare_competitor` | 4 | Анализира сайт на конкурент и сравнява GEO сигналите му с твоите. |
| `gsc_top_queries` | 1 | Реални заявки, кликове, импресии и позиции — моментна снимка. |
| `gsc_compare` | 2 | Два периода един до друг: кой печели, кой губи, кое е ново и кое е изчезнало. Инструментът за „защо паднахме“. |
| `gsc_opportunities` | 2 | Бързите победи: заявки на позиция 5–20 и страници в топ 10 с нисък CTR. |
| `gsc_inspect_url` | 1 | Индексиран ли е адрес, кога е обходен, блокира ли го robots.txt. |
| `gsc_list_sites` | 0 | Имотите в Search Console, до които акаунтът има достъп. |
| `ga4_overview` | 1 | Сесии, потребители и ангажираност по канал, страница или източник. |
| `ga4_ai_traffic` | 1 | Колко посещения идват от AI асистенти. |
| `ga4_list_properties` | 0 | GA4 имотите, до които акаунтът има достъп. |
| `generate_schema` | 2 | Валидна schema.org JSON-LD разметка, сглобена от код и проверена. |
| `generate_llms_txt` | 3 | `/llms.txt` от реалните адреси на сайта плюс блок за `robots.txt`. |
| `content_brief` | 4 | Задание за статия: отговор в първите 60 думи, структура, FAQ, същности. |
| `keyword_ideas` | 2 | Идеи за ключови думи и въпроси, групирани по намерение. |
| `create_task` | 0 | Записва задача в таблото — за да не остане съветът само в чата. |
| `list_tasks` | 0 | Отворените задачи по приоритет. |

## Откъде идват числата

| Число | Източник | Забележка |
|---|---|---|
| Позиции, кликове, импресии, CTR | Search Console API | Реални измервания. Изостават с 2–3 дни — затова заявките винаги свършват на `днес − 3`. |
| Разлики между два периода | Search Console, пресметнати в кода | Аритметика, не преценка: `gscCompare` съединява двата периода по ключ и вади разликата. Моделът обяснява защо, не смята колко. |
| Сесии, потребители, ангажираност | GA4 Data API | Реални измервания. |
| Трафик от AI асистенти | GA4, по източник | Груба мярка: GA4 няма собствена група за AI, разпознава се по referrer. Част от посещенията идват без източник. |
| Видимост в AI отговори | Реални заявки към модели, при които търсенето **наистина е минало** | Измерване, не оценка. Дял на отговорите, в които брандът е споменат. Дали е търсено се чете от отговора, не се обявява. Двигател, който не отговори, се брои като грешка, а не като нула. |
| Познатост без търсене | Същите въпроси към модел **без** интернет | Отделно число. Не е видимост — показва дали брандът е влязъл в данните за обучение. |
| Технически резултат, GEO резултат | Обхождане + правила в кода | Детерминистично. Две еднакви обхождания дават едно и също число. |
| Идеи за ключови думи | Модел | Предложения без обеми. За реални числа — `gsc_top_queries`. |

## Разделението „код или модел“

Структурата се пресмята с код, текстът се пише от модел.

JSON-LD, което понякога е валидно, е по-лошо от липсващо — търсачката
отхвърля целия блок. Затова скелетът се сглобява детерминистично в
`src/lib/generators.ts`, проверява се, и моделът попълва само полетата с
думи. По същата причина „споменат ли е брандът в този отговор“ е текстов
разбор, а не втори модел: това е факт, не преценка, и трябва да дава един и
същ резултат при две минавания през същия текст.

## Добавяне на нов инструмент

В `src/lib/tools.ts`, към обекта `TOOLS`:

```ts
my_tool: {
  credits: 2,
  running: 'Показва се, докато работи…',
  schema: {
    name: 'my_tool',
    description: 'Кога ботът да го ползва. Пише се за модела, не за човека.',
    parameters: { type: 'object', properties: { … }, required: […] },
  },
  async run(args, context) {
    return {
      summary: 'Това вижда моделът: кратко, с числа, без украса.',
      data: { … },      // това вижда потребителят като карта под отговора
      kind: 'my-kind',  // как я рисува `renderCard` в src/scripts/chat.ts
    };
  },
},
```

Регистрацията е достатъчна — `toolSchemas()` го подава на модела, а
`/api/tools` го прави достъпен и за бутон в таблото.
